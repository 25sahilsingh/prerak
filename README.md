# Prerak · प्रेरक

A Next.js web app that helps women and girls in Uttar Pradesh find government schemes (64 UP and central schemes, status as of 23 Oct 2026). It has:

- a searchable catalogue of all schemes with eligibility, documents, how to apply and official links;
- a Hindi / English / Hinglish chatbot that answers only from the scheme document (hybrid RAG), uses the user's saved profile to judge eligibility, and remembers the conversation;
- answers generated by **the user's own local model** (Ollama, LM Studio, llama.cpp, vLLM - any OpenAI-compatible server). No cloud AI.

## Quick start

Requires Node 20+, git, and a model server (see [Connect your own model](#connect-your-own-model)).

```bash
git clone https://github.com/25sahilsingh/prerak.git
cd prerak
npm install
npm run dev        # open http://localhost:3000
```

The first `npm run dev` builds the scheme database from the PDF (a few minutes once; it downloads a ~120 MB embedding model). Later starts are instant.

Then open **Settings** in the app, enter your model server's address (and API key if it needs one), press **Test connection**, pick the model and **Save**.

To rebuild the scheme data by hand: `npm run ingest`.

## Connect your own model

Start any OpenAI-compatible model server, then in the app go to **Settings**:

1. Tap a preset (or type the URL):

   | Server | Base URL | Start it with |
   | --- | --- | --- |
   | Ollama | `http://localhost:11434/v1` | `ollama pull qwen2.5:7b` |
   | LM Studio | `http://localhost:1234/v1` | Developer tab > Start Server |
   | llama.cpp | `http://127.0.0.1:8080/v1` | `llama-server -m model.gguf --port 8080` |
   | vLLM | `http://localhost:8000/v1` | `vllm serve <model> --port 8000` |

2. Press **Test connection**. The app lists the models the server has; pick one.
3. Add an API key only if your server needs one. Press **Save**.

Settings are stored in `data/app.db` and apply immediately. `.env.local` (`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`) is only a fallback used before anything is saved.

For good Hindi answers use a multilingual 7B-9B model (Qwen 2.5/3, Llama 3.1, Gemma). Hindi text uses many more tokens than English, so it is slower on small devices.

### Example test setup (Jetson Orin over SSH)

During development the model ran on a Jetson Orin Nano (llama.cpp, Granite 4.2 8B), reached privately with `ssh orin_model` (forwards laptop `:8080` to the Orin) and the llama.cpp preset `http://127.0.0.1:8080/v1`. Any machine running a model server works.

## How it works

```
PDF --(npm run ingest)--> SQLite: schemes, 322 chunks (5 per scheme + guide), FTS5 keyword index, embeddings
question --> hybrid search (FTS5 BM25 + multilingual-e5-small vectors, reciprocal rank fusion)
         --> boosts for schemes named in the question and schemes matching the profile
         --> hides fake/closed schemes unless the user asks about them
         --> prompt (rules + profile + conversation summary + last 6 messages + top sources)
         --> your model (streamed) --> answer with scheme-ID source chips
```

- Embeddings run on the app machine (CPU), so the model server only generates text.
- Hindi/Hinglish words are mapped to English keywords for the keyword search (the PDF is English).
- With llama.cpp, the app renders the prompt via `/apply-template` and uses `/v1/completions`, because llama.cpp's chat-output parser can cut off Hindi answers.
- Long chats are summarised every 10 messages to stay inside small context windows.
- **Link and helpline guard** (`lib/rag/guard.ts`): small models sometimes mistype links or numbers (e.g. `pmmvy.wcd.gov/in`, `1811`). After each answer, every URL, email and helpline-like number is checked against a whitelist built from the scheme data. Near-misses are replaced with the closest official value, unknown ones are removed with a pointer to the verified links, and the corrected answer replaces the streamed one. Each answer also shows an "Official links and helplines (verified)" box filled straight from the database, never from the model.

## Checks

```bash
npm run typecheck
npm run check:guard   # offline: the guard fixes known bad links/numbers and leaves amounts, years and real helplines alone
npm run e2e           # needs the app running (npm start) and a reachable model; asserts no unverified link/number in answers
```

Key files: `scripts/ingest.ts`, `lib/rag/retrieve.ts`, `lib/rag/profile.ts`, `lib/rag/prompt.ts`, `lib/llm.ts`, `lib/settings.ts`, `app/api/chat/route.ts`.

## Updating the scheme data

Replace `Women_Schemes_UP_Women_Oct2026_RAG.pdf` with a new version in the same format and run `npm run ingest` again, then restart the app.
